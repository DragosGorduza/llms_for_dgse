# runs/

Output of experiments. Everything here except this file is gitignored.

Layout: `runs/<experiment_id>/<run_id>/` with

- `config.resolved.yaml` : fully resolved config for this cell
- `manifest.json` : config hash, versions, timestamps, status, what was modified and how
- `llm_calls.jsonl` : one `LLMCall` per line (prompt, response, parsed, cache hit); no keys
- `shock_paths.parquet` : the path injected into each model variable
- `trajectories.parquet` : long format `(scenario, variable, t, value)` for baseline, shocked and irf; when the scenario mixes classic and LLM shocks also `classic`, `llm`, `irf_classic`, `irf_llm`, `irf_interaction`
- `metrics.json` : peak, time of peak, cumulative effect, half-life per variable (of the combined response)
- `metrics_arms.json` : only for classic + LLM scenarios; the same metrics for the classic, LLM, combined and interaction responses
- `report.md`, `figures/` : generated by `dgse-llm report`

`runs/<experiment_id>/index.parquet` lists every cell of a sweep with its status, its axes (`prompt`, `persona`,
`scenario`, `model_info`) and the raw `answer`. Two more files summarise the sweep:

- `summary.parquet`: one row per (llm, prompt, persona, scenario, model_info): `n` draws, `answer_mean/std/min/median/max`
  and `peak_<variable>_mean/std` of the model responses. `n` is 1 at temperature 0; otherwise `repeats`.
- `info_effect.parquet`: mean answer with and without the model info in the prompt, and the difference.

`runs/<experiment_id>/evaluations/` (from `dgse-llm evaluate <experiment_id>` or `run --evaluate`) compares the
specifications like with like along each axis; see `src/dgse_llm/evaluation/README.md`.

## Errors

A failed run is logged as `runs/<experiment_id>/errors/<ErrorName>/<run_id>.json`, with the error name taken from the
underlying cause (for example `ParseError` when the LLM's answer is invalid or outside `answer_bounds`). The file holds
the error message, the run's axes and every LLM call: the prompt that was sent and the response text that came back.
The same calls are also in the run's own `llm_calls.jsonl`. The log is removed when the run later succeeds.

## Re-running

Running the same experiment again keeps every run that finished `ok` with an unchanged setup: it is not solved again
and its files are not touched (`[skip]` in the output). A run is run again when it failed, when anything in its setup
changed (model parameters, `T`, LLM settings, scenario, conversion, answer bounds), or when the prompt that would be
sent differs from the recorded one (an edited template). Changing `repeats` only adds the new draws. At temperature 0
the LLM answers are also cached in `.llm_cache/`, so re-run cells cost no API calls. `--force` runs everything again.
Before a run is re-run, its old files are deleted, so a failure cannot leave stale results next to a `failed` manifest.
